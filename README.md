# Спортивный клуб — база данных

Учебная база данных SQLite для спортивного клуба: участники, тренеры, абонементы, оплаты, расписание занятий, записи и посещения.

## Таблицы и зачем они нужны

| Таблица | Что хранит | Связи |
|---|---|---|
| `members` | участники клуба | — |
| `trainers` | тренеры | — |
| `memberships` | купленные абонементы и срок их действия | участник → много абонементов |
| `payments` | оплаты абонементов | абонемент → одна или несколько оплат |
| `classes` | занятия в расписании: время, зал, число мест | тренер → много занятий |
| `bookings` | записи участников на занятия | связка «многие ко многим» между `members` и `classes` |
| `visits` | посещения клуба (отметка на входе) | участник → много посещений |

У каждой таблицы свой главный ключ `id`. Схема связей — в файле `erd.png`.

## Ограничения

- **NOT NULL** — на всех важных полях: имена, e-mail, даты, цены, время занятий, ссылки на другие таблицы.
- **UNIQUE**:
  - e-mail участника и тренера не повторяется;
  - один участник не может дважды записаться на одно занятие (`bookings`: пара `member_id` + `class_id`).
- **CHECK** — 8 проверок:
  - участнику на момент вступления не меньше 14 лет;
  - вид абонемента — только «Месячный», «Квартальный» или «Годовой»;
  - цена абонемента и сумма оплаты больше 0;
  - абонемент и занятие заканчиваются позже, чем начинаются;
  - способ оплаты — только `card`, `cash` или `transfer`;
  - количество мест в группе больше 0.
- **FOREIGN KEY** — все ссылки между таблицами: нельзя записать на занятие несуществующего участника.
- **Индексы** — для частых запросов: абонементы участника, занятия по времени начала, записи по занятию, посещения участника по дате.

## Проверочные запросы (`checks.sql`)

Отчётная дата в запросах зафиксирована — 15.11.2026, чтобы результат не менялся со временем.

1. Кто сейчас имеет активный абонемент.
2. Сколько людей записано на занятия по датам.
3. Список тренеров и их занятия.
4. Участники, которые не посещали клуб больше 30 дней или не приходили ни разу.
5. Топ-3 самых популярных занятий.
6. Выручка клуба по видам абонементов.
7. Конфликты в расписании: у одного участника пересекаются занятия.
8. Заполненность занятий: сколько мест занято из доступных.
9. Абонементы, которые заканчиваются в ближайшие 14 дней — кому напомнить о продлении.

## Как запустить

1. В DBeaver создать новое подключение SQLite с новым файлом `sports.db`.
2. Открыть и выполнить `schema.sql` (Alt+X) — создадутся таблицы.
3. Выполнить `seed.sql` — загрузятся 48 строк тестовых данных.
4. Выполнить `checks.sql` — каждый запрос откроется на отдельной вкладке результатов.

Скриншоты работы — в папке `screenshots/`.
